# 项目修改记录

## 2026-11-19 · 修复波形导入

- **问题**：旧设备页把 `.pulse` 文本送给二维码解码器。控制台导入以 Hub 的内存列表重建磁盘库，连续导入可能漏掉上一批；旧 Hub 查询单设备波形还会把私有项追加到公共内存列表，反复查询会重复追加。
- **修改**：控制台和内嵌设备页都支持 `Dungeonlab+pulse:` 文本及波形二维码图片，复用随包的解码器，在浏览器后台解析。修复单点渐变产生无效频率的边界情况。公共库另支持单项、数组和 `pulseList` 格式的 JSON / JSON5（含 BOM）；缺 ID 的波形使用与原 Hub 相同的内容 ID。
- **数据处理**：公共导入在锁内从实际磁盘库读取、保留旧条目和扩展字段、备份原字节并替换。相同 ID 和帧跳过且保留原名称；相同 ID 对应不同帧则整批不写。检查私有列表不再改变公共列表。写入后单独确认 Hub 是否已经加载，并保留表单未保存的选择。
- **验证**：60 项 Python 测试和 3 项前端解析测试通过。使用独立临时目录运行随包 Hub，在无设备连接的 Chromium 中从控制台导入静默 `.pulse`，确认规则列表可见；再导入相同数据的二维码，确认判重。Hub 自己的页面地址也验证了两种格式的解码。连续查询临时私有会话，确认私有项没有混入公共列表。实际 `data/pulse.json5` 修改前后 SHA-256 一致。
- **使用与范围**：退出现有控制台及独立运行的旧 Hub，重新双击 `start.bat` 加载修复。没有启动游戏或测试硬件；训练场由用户手动验证。压缩包先解压，非波形配对码不可导入。
- **可复查**：`python_env\python.exe -m unittest discover -s tests`；`node --test tests/pulse-import.test.mjs`。修复前的相关源码快照：`backups/before-wave-import-20261119-2230.zip`。更早的整合与直播悬浮窗修改记录见 [审计记录](docs/AUDIT.md)。
